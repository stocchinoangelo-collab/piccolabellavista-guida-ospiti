# Beach migration plan

## Goal
Move the legacy `BEACHES` dataset in `js/data.js` toward the Concierge content model without changing production behavior yet.

## Safety rule
The migration is intentionally conservative. Mechanically migrated records are created as:

- `status: draft`
- `access: guest`
- `verification.status: unverified`
- `migration.reviewRequired: true`

Nothing generated by the migration is ready for public publication until reviewed.

## Why beaches first
The legacy beach records already contain the most useful ingredients for a future proactive Concierge: coordinates, drive time, services, parking, access, seasonality, wind suitability, `go` and `avoid` advice. This also makes them high-risk if stale.

## Verification priority
Each beach must be reviewed in this order:

1. Identity and coordinates.
2. Access restrictions / reservation requirements.
3. Parking availability and rules.
4. Services and seasonal openings.
5. Estimated drive time from Piccolabellavista.
6. Wind advice and safety wording.
7. Angelo & Viviana editorial recommendation.
8. Public vs guest-only access level.
9. Photo rights and credits.
10. IT/EN/DE editorial consistency.

## Volatility classes

### High volatility
- reservation requirements
- access quotas
- parking rules/prices
- seasonal services
- temporary closures

These need a recent authoritative source before being shown as current.

### Medium volatility
- drive time
- crowd advice
- service availability

These should be presented as estimates and periodically reviewed.

### Low volatility
- coordinates
- orientation/facing
- general landscape description

Even these should be checked once during migration.

## Migration command

```bash
node scripts/migrate-beaches.mjs
```

Expected output:

`data/concierge/beaches.generated.json`

The generated file is an intermediate audit artifact, not a production source.

## Next step
After generation, create a human-reviewed `data/concierge/beaches.json`. Only reviewed records should move from `draft/unverified` to `active/verified`.
